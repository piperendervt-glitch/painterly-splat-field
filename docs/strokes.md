# 筆跡の粒：3D の形を、絵画のタッチの粒に変える

タブ「5 筆跡の粒」（`studio/strokes.html`）。今までの「粒の空間」は、絵の 1 画素を 1 粒として置くので、絵に写っていない所は穴になり、視点ごとに絵を描かせて継ぎ足していた。
ここでは順番を逆にする：**先に 3D の形があり、絵画 1 枚からタッチ（筆の大きさ・長さ・向き・色の決まり）を測って、形の表面に筆跡としてまく**。
形の裏も、遠くも、同じ決まりでまくので、どこから見ても同じタッチになる。絵に写っている所は、絵の色と筆の向きをそのまま写す。

## 流れ

| 段 | 何をするか | どこ |
| --- | --- | --- |
| 1 | 参照の絵のカメラで形を CPU で描き、画素ごとの奥行き・三角形・面の向き・種類・物体を作る | `shared/strokefield.js` の `rasterize` |
| 2 | 絵から筆跡を測る（種類ごと） | `shared/brushstats.js` の `measureStrokes` |
| 3 | 色の決まりを学ぶ（物体ごと） | `strokefield.js` の `learnModels` |
| 4 | 8 分木の箱ごとに、表面へ筆跡をまく | `strokefield.js` の `generateNode`（Web Worker：`studio/strokeworker.js`） |
| 5 | 画面の上で筆の太さが絵と同じくらいになる箱を選んで描く（LOD） | `studio/strokes.js` の `select` |

### 2. 筆跡を測る

- **筆の向き**：明るさの勾配の構造テンソル（ぼかし 1 画素、ならし 5 画素）。勾配と直交する向きが筆の向き、固有値の差がはっきりさ。
- **幅と長さ**：細かい明暗（ぼかし 0.8 − ぼかし 10）の自己相関を、筆の向きに沿って・横切って測り、半分に落ちる距離 × 2。長さ L の四角い筆跡なら自己相関は 1 − d / L なので、半分になるのが L / 2。
- **向きの分布**：絵の上の角度（18 段）と、面の上の角度（面に沿って上を基準。ほぼ水平な面は参照のカメラの右を基準）の 2 つ。面の上の角度は、絵の筆の向きを、その画素に写っている面の上へ写して数える。
- **毛の筋の強さ**：とても細かい明暗 ÷ 筆跡の大きさの明暗。

測った値は「絵を調べる」画面で、絵に重ねて見られる（筆の向き・はっきりさ・測った幅 × 長さの四角・種類・境目）。

### 3. 色の決まり

物体ごと（画素が少なければ種類ごと → 全体）に：

- **陰影**：色 = c0 + C · 面の向き（1 次式、少し引き締めて当てはめる）。絵の光の当たり方を、面の向きから引ける形で覚える。写っていない裏の面は、この式の延長で暗くなる。
- **色の揺らぎ**：絵の色 − 陰影 の見本（最大 4096 個）を明るさの順に並べたもの。写っていない所では、場所でなめらかに変わるノイズで見本を引くので、隣どうしの筆跡は似た色になり、絵のような色のまとまりができる。ノイズは決まった大きさ（48・16・6・2・0.7・0.25 m）を重ねたもので、筆跡の長さより細かい段は使わない（遠くの粗い筆跡でも模様が変わらない）。
- 明るさは、絵で見た範囲（1〜99%）に収める。
- 空は向きだけで決まる（色 = c0 + C · 視線の向き）。

### 4. 筆跡をまく

- 8 分木の根は形全体を囲む立方体。深さ l の箱の筆の幅 = 箱の一辺 ÷ 2^l ÷ 40（設定 `across`）× 種類ごとの倍率（種類の幅 ÷ 全体の幅）。長さ = 幅 × 種類の「長さ÷幅」（1.2〜8）。
- 三角形を箱で切った多角形に、面積 × 重ね塗りの厚さ ÷（幅 × 長さ × 0.62）本をまく。
- 1 本ごとに：絵に写っているか（参照のカメラの奥行きと比べる）、写りの良さ q（面の向きと視線の角度、境目のそばは下げる）を調べ、
  - 色 = 学んだ色 と 絵の色 を q でまぜる
  - 向き = 決まりの向き（面の上の角度の分布から、場所でなめらかに変わるノイズで引く）と、絵の筆の向き（はっきりさで重み）を q でまぜる
- 空は、半径 1 の球の上にまき、描くときはカメラを中心に半径 3000 m に置く（いつも無限に遠い）。

### 5. 描き方と LOD

- 筆跡 1 本 = 面に沿った四角い板 1 枚（向き T、幅、長さ）。筆の形の絵（`studio/brushtex.js`。8 種類、入りは丸く抜きはかすれる、毛の筋）の半分より濃い所だけを描く（不透明）。
- 不透明なので、遠い順の並べ直しは要らない。同じ面の上で重なる筆跡は、塗る順番（0〜1）× 幅 × 0.3 だけカメラの方へずらし、後から塗った筆跡が上に来る。
- 箱を選ぶ：画面の上での筆の幅（箱の筆の幅 × 画面の焦点距離 ÷ 箱までの距離）が、目標（絵の筆の幅 × 画面の高さ ÷ 絵の高さ × 「筆の大きさ」）の √2 倍より太ければ、子の箱に分ける。子の箱がまだできていなければ、親の箱を描いたまま作るのを待つ。
- 箱は Web Worker で、粗い段から順に作る。粒の数が 800 万本を超えたら、しばらく使っていない箱から捨てる。
- 筆の向き「画面に合わせる」：筆跡ごとに、絵の上の角度（写っていれば絵の値、なければ種類の分布から）を持っていて、いまの画面の右・上の向きから筆の向きを作り直す。

## 筆跡の列

| 列 | 中身 |
| --- | --- |
| P | 位置 xyz（空は向き）、幅（m。空はラジアン） |
| N | 面の向き xyz、長さ（m。空はラジアン） |
| T | 筆の向き xyz（ワールド）、絵の上の筆の角度（ラジアン） |
| K | 色 rgb（sRGB 0〜1）、塗る順番 |
| M | 種類、絵から来た割合（0〜1）、筆の形の番号（0〜7）、8 分木の深さ |
| G | 陰影だけの色 rgb、毛の筋の強さ |
| O | 物体の札（書き出し用） |

## 確かめ方

- 参照に A だけを使い、B から見て B の絵（参照に使っていない）と重ねて見比べる。B は A に写っていない面（アーチの左の側面、塔の左側）を含む。
- 「絵に写っている色を使う」を 0% にして作り直すと、写っている所も決まりだけで塗る。A から見て A の絵と重ねると、決まりだけの色がどれくらい絵に近いかが分かる。
- 「LOD の段」で、近くは細かい段・遠くは粗い段になっているか、「描いている箱を見る」で箱の大きさを見る。

## 絵 1 枚の場面（ジャット島）と点描

プレビズの無い場面（`scenes/<名前>/`。`painting/build.mjs`・`relabel.mjs` の書き出し）でも同じ道具が動く（`studio/strokescene.js` が場面を見分ける）。

- **形**（`shared/paintscene.js`）：背景の面（奥行きの絵から、物の所を埋めたメッシュ。物の後ろには必ず回す）＋ 物ごとの形 ＋ 絵の外へ続く土台の平面。物の一覧は物体の札の絵そのものから作る。物ごとの形は、いまは絵の輪郭をふくらませた表と裏のある形（断面が円に近い）。280 m より遠い物は 280 m の壁として置く。
- **点描の見分け**（`shared/brushstats.js`）：筆跡の幅と長さを、粗い帯（筆の向きがはっきりした所）と細かい帯（全部の画素）の 2 通りで測る。細かい帯の縦横比が 1.7 より小さければ点（`dot` = 1）。ジャット島は幅 2.3 px・長さ 3〜3.7 px で、全部の種類が点になる。
- **点の描き方**：点は丸い筆（筆の形 8〜15 番）で、面に寝かせず、いつもカメラの方を向く。斜めに見た地面でも、絵と同じ大きさの点に見える。草も立てない。色は、隣どうしをばらばらに引く（点ごとに違う色を置く塗り方）。
- **数の調整**：点は斜めに見ても小さくならないので、段を粗くしない。代わりに、平らな箱を斜めに見るときは、描く数を減らす（箱の中の筆跡は順不同なので、先頭から何割かを描く）。
- **色を写す所**：物の形と絵の輪郭はずれるので、絵の色を写すのは、絵のその画素が同じ物体のときだけ。浅い角度で見えている地面も写す（1 筆は絵の 1 点の色を取るだけなので、引きのばしにならない）。
- **計算だけで描く道具**（`paint/strokes-render.mjs`）：同じ筆跡を、GPU を使わずに絵にする。視点を動かした絵も出せる。

```
node paint/strokes-render.mjs --scene scenes/jatte-best --out paint/out/strokes --views ref,right,left,near,fwd,turn,up,back --modes color,source
```

## まだやっていないこと

- 絵 1 枚の場面で、物ごとの 3D モデル（TRELLIS・Hunyuan3D の `.glb`）を、ふくらませた形の代わりに置くこと。
- 空の点は、数に上限（150 万）があるので、点描ではまばらになる（地の色が見える）。見えている所だけ作る仕組みが要る。

- 光の付け替え・風・足跡（「粒の空間」の `studio/fx.js`）はまだつないでいない。
- 物体ごとの 3D モデル（TRELLIS・Hunyuan3D の `.glb`）や地形の読み込み。いまはプレビズの形だけ。
- 段の切り替わりのなめらかな移り変わり（いまは切り替わる瞬間に筆跡が入れ替わる）。
