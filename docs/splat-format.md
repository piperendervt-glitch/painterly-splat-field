# 粒が持つ情報と、光の付け替え

粒は「絵の 1 画素」から作る。色だけは絵から取り、それ以外は同じ画素のプレビズの絵から取る。穴埋めで足す粒も、その視点のプレビズの絵から同じ仕組みで取る。

## 粒ごとの列

`studio/splat.js` の `COLUMNS`。列を足すときはここに 1 行足す。知らない列は無視し、渡されなかった列は既定値で埋める。

| 列 | 型 | 中身 | どこから取るか |
| --- | --- | --- | --- |
| `position` | float32 × 3 | 位置（m、ワールド座標） | プレビズの奥行き `X_depth.png` とカメラ情報 |
| `size` | float32 | 粒の間隔（m） | 奥行き × 画素の間隔 ÷ 焦点距離 |
| `color` | uint8 × 3 | 絵のままの色（sRGB） | 絵画（または下絵）の同じ画素 |
| `type` | uint8 | 種類の札。0 は空 | `X_type.png` |
| `object` | uint16 | 物体の札。0 は物体なし | `X_object.png` |
| `normal` | int8 × 3 | 面の向き（-127〜127） | `X_normal.png` |
| `sunVis0` | uint8 | 絵を描いたときの日なた（255）・影（0） | `X_sun.png` |
| `sunNow` | uint8 | いまの太陽での日なた・影（確かめ用） | ふだんは描くときにシェーダーが計算するので使わない。以前の CPU の計算と見比べるときだけ埋める（`cpuSun()`） |
| `sway` | uint8 | 揺れやすさ | 種類の一覧の `sway`（いまは種類ごとに一律） |
| `view` | uint8 | どの視点（や穴埋めの回）から来たか | 置くときに記録。奥行きの絵からの粒は視点の番号、SHARP の粒は「視点の数 + 番号」、背後の層は「視点の数 × 2 + 番号」 |
| `edge` | uint8 | 奥行きの境界からの距離（画素） | `X_depth.png` |
| `labelEdge` | uint8 | 種類・物体の境目からの距離（画素） | `X_type.png` と `X_object.png` |
| `lift` | float32 | 影を調べるときに面から浮かせる量（m） | 奥行きの刻みの粗さ |
| `opacity` | uint8 | 不透明さ（0〜255） | 奥行きから置いた粒は 255。SHARP の粒は SHARP の値（`sharp/README.md`） |
| `cov` | float32 × 6 | 粒の形（共分散 xx, xy, xz, yy, yz, zz。m²） | 面の向きと元の視点からの向きで決めた「面に沿う楕円」。SHARP の粒は SHARP の楕円体。空は丸（[angle-artifacts.md](angle-artifacts.md)） |
| `layer` | uint8 | 層。0 = 絵に見えていた面、1 = 背後の層、2 = 周囲の地面、3 = 取り込んだ世界 | 置くときに記録。背後の層は、手前の物の後ろに背景を伸ばして作った粒。周囲の地面は、絵の外の地面を土台の平面の上に置いた粒（`view` は 視点の数 × 3）。取り込んだ世界は、外の道具で作った `.ply` の粒（`view` は 視点の数 × 3 + 1。種類・面の向き・日なたは仮の値） |
| `skyFrom` | uint8 | 天球の粒の出どころ。0 = 天球の粒ではない、1 = 絵、2 = AI が描いた空、3 = ツール内で埋めた空 | 空の地図（`studio/skydome.js`） |

空の粒は、ほかの粒と別に持つ（天球）。位置は「向き × 半径 3000 m」で、描くときはいつもカメラを中心に置く。列は上と同じで、`type` は 0（空）、`object` は 0、`view` は絵から来た粒だけが持つ。

## 一覧で持つもの

- 種類の一覧：`shared/labels.js` の `TYPES`（番号、名前、色分けの色、揺れやすさ `sway`、光の受け方 `light`、雪が積もるか、水面か、当たり判定 `solid`、足跡が付くか `tracks`、手前の物か背景か `layer`）。`cameras.json` の `labels.types` にも書き出す。
- 物体の一覧：`cameras.json` の `labels.objects`（番号、名前、種類、プレビズでの色、大きさ）。
- 絵を描いたときの光：`cameras.json` の `paint_light`（太陽の方向と、下絵 2 枚の光の強さ）。
- 視点の一覧：`cameras.json` の `views`。

## 光の式

`shared/light.js`。プレビズの下絵も、粒の光の付け替えも、同じ式を使う。

```
空の光  hemi(n) = 0.8 + 0.2 * n.y
明るさ  L = ambient * hemi(n) + sun * max(n・l, 0) * vis
        n = 面の向き、l = 太陽の方向、vis = 日なた 1・影 0

粒の色 = 絵の色 × 今の明るさ ÷ 描いたときの明るさ
```

| 絵の描かせ方 | 描いたときの明るさ | 意味 |
| --- | --- | --- |
| 光の少ない絵（`--light flat`） | `hemi(n)` | 絵は物の色だけ。日なた・日陰・影は全部計算で足す。絵に影が無いので、二重にならない |
| プレビズの光に従う絵（`--light previz`） | `0.45 * hemi(n) + max(n・l0, 0) * vis0` | 絵に描かれた光と影を割り戻してから、今の光を掛ける（差分方式）。絵の影が下絵とずれると、ずれた分が残る |

空の粒（種類 0）は太陽の計算をせず、空の光の色と強さだけを掛ける。`light: 'self'` の種類（灯りなど）は暗くしない。

この式は描くとき（シェーダー、`studio/fx.js`）に粒ごとに計算する。太陽を動かしても粒の配列は書き直さず、太陽から見た奥行きの地図（1024 × 1024、プレビズの形だけ）を 1 枚作り直して渡すだけなので、時間帯を連続で動かせる。以前の CPU の計算は、確かめ用に `relitCpu` の表示として残してある（WebGL 2 のヘッドレスで撮り比べて、差は 1/255 以内）。

## 描画用の配列

粒ごとの列から、描画用に vec4 を 4 本作る（`sendSource`。遠い順の並べ直しは `studio/sortworker.js`）。WebGPU は頂点バッファの本数に上限があるので、列ごとには分けない。

| 配列 | 中身 |
| --- | --- |
| A | 位置 xyz、粒の間隔 |
| B | 表示する色 rgb（リニア）、奥行きの境界からの距離（整数部）＋「1 − 不透明さ」× 0.45（小数部） |
| C | 空かどうか、視点、揺れやすさ 0〜1、光の受け方（0 太陽 / 1 空 / 2 自分で光る）＋ 足跡が付くなら 4 |
| D | 面の向き xyz、描いたときの日なた 0〜1 |

## 動き

どれも粒の位置や色を描くときに動かすだけで、粒の列は書き換えない。切れば元の絵に戻る。

| 動き | 使う札 | 仕組み |
| --- | --- | --- |
| 風の揺れ | `sway`（種類の `sway`） | 風下へ進む大きな波 ＋ 横切る細かい波 ＋ ゆっくりした強弱で、粒を風下へずらす。揺れた分だけ明るさも波打つ |
| 草よけ | `sway` | 歩く人の足元（当たり判定の位置）から半径の中の粒を、外へ押して少し倒す |
| 足跡 | 種類の `tracks` | 歩幅 0.65 m ごとに、立っている面の種類が `tracks` なら、足の形を足跡の地図（2048 × 2048、128 m 四方、1 画素 6.25 cm）に押す。地図の濃い所の粒は暗くなり、揺れにくくなる |

## 時間帯

`shared/light.js` の `dayLight(時刻)` が、時刻（0〜24）から太陽の方位・高さ・色・強さと、空の光の色・強さを返す。太陽は 6 時に方位 90° から昇り、12 時に方位 0° でいちばん高く（62°）、18 時に方位 270° へ沈む。夜は月が同じ道を通る（弱く青い光で、影も月の向きに落ちる）。色と強さは `DAY_KEYS` の表（夜・夜明け前・日の出・朝・昼・午後・夕焼け・日没・たそがれ）のあいだをなめらかにつなぐ。「時間を進める」で時刻が自動で進み、朝・昼・夕・夜のボタンは決まった時刻へ飛ぶ。
